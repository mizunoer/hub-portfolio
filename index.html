Dallin: AI does the routine work, people handle the exceptions

Dallin designs operations where AI does the routine reading, sorting and drafting, and people make the calls that need judgment. Case study: a legal document review line

A deadline-bound audit of scanned legal case documents, rebuilt so AI does the reading and people only see the documents that need judgment. It runs entirely on the owner's own hardware, because the documents may never leave it.

  1. Every page is read by AI. Scans are queued by priority, turned into text and read for the fields the audit needs, across two GPU machines working the same queue.
  2. Two independent reads must agree. A document settles on its own only when two separate reads give the same answer. A model's answer counts only when a plain text check agrees with it.
  3. A third read breaks ties. When the two reads disagree, a third read decides two of three. Only what is still unsettled goes to a person.
  4. People get a review page, not a pile. The exceptions arrive with the page crop and both readings side by side, so the reviewer decides in seconds instead of re-reading the file.
  5. Every decision is on record. Each document gets a written record of what was read, which reads agreed and who decided, bundled per batch for the audit trail.

Result: The human work moved from reading every document to deciding the exceptions, and the line runs unattended between reviews.

Demo versus production

A demo works once. These are the things that broke when the system did real work every day, and what now keeps it running.

what brokewhat keeps it running now
A model reader leaked memory under steady loadIt now runs with a hard memory ceiling and restarts itself cleanly; the queue picks up where it stopped.
Models quietly slid off the GPU and slowed every answerA residency check every 5 minutes reloads any model that spilled onto the CPU, before anyone notices.
A machine could hang overnightOut-of-memory guards, a watchdog and a peer machine that can reboot it keep the line up without a person at the keyboard.
Unattended agent sessions went idleA keep-alive restarts them only when they are idle, never in the middle of a job.
A new model can look better than it isA challenger replaces a model only when it measures 30% better on an in-house test at the same cost and speed, and every switch has a rollback.
Things break silentlyAn end-to-end smoke test runs every day and its result is published on this page.

Workflows in daily use

Each workflow, the manual work it replaced, how much of it runs on its own, and what a person still decides.

Label every request

Runs on its own

Before: Deciding by hand which model each question should go to

Now: Every incoming request is labelled by a small model and sent to the right place.

A person still decides: Nothing day to day; the labelling model is swapped only when a better one measures better.

Pick the local model for each category

AI proposes, a person approves

Before: Reading benchmarks and swapping model tags by hand

Now: The model for each kind of work is chosen from measured results on an in-house test.

A person still decides: Approves or rejects each proposed switch, with the measurements in front of them.

Send work to free external models

A person approves every item

Before: Paying for every answer, or keeping every answer on one GPU

Now: Routine, non-sensitive work can go to free external models instead of paid ones.

A person still decides: Approves each kind of work before any of it leaves; sensitive work never does.

Remember what matters

Runs on its own

Before: Repeating context in every chat

Now: Context from past work is kept and recalled automatically.

A person still decides: Corrects, marks private or deletes anything it kept.

Turn documents into markdown

Runs on its own

Before: Copying text out of PDFs, Word and slides by hand

Now: PDFs, Word files, slides and scans become searchable text on arrival.

A person still decides: Nothing; scans stay on the owner's hardware.

Triage mail

Runs on its own

Before: Reading every message to find what needs a reply

Now: Incoming mail is sorted and summarised into one short brief.

A person still decides: Reads the brief and acts on what matters.

Draft mail replies

A person approves every item

Before: Writing routine replies from scratch

Now: Routine replies arrive as drafts.

A person still decides: Approves every draft; the system never sends mail itself.

Rate external models

Runs on its own

Before: Trusting leaderboards

Now: External models are tested on synthetic work before they are trusted.

A person still decides: Nothing; no real data is ever sent.

Set up a new machine

AI proposes, a person approves

Before: An evening of installs per machine

Now: A new machine sets itself up from a USB stick.

A person still decides: Plugs in the stick and picks it at boot.

How the work is run

The operating habits behind the system.

Map the work before automating it

Start from the person doing the job: what they read, what they decide, where they wait. Automate the reading and the routing; keep the judgment with them.

Decide where AI acts alone

Every workflow has a written rung: runs on its own, AI proposes and a person approves, or a person approves every item. Moving up a rung takes evidence.

Measure before claiming

Baselines first, counts per rule before anything is called done, and the same numbers reviewed until they move.

Decide in writing

A numbered, never-rewritten record for every design choice, so anyone can see why the system works the way it does.

Privacy by design

Sensitive work never leaves the owner's hardware. The rule is enforced in code, and every public output, this page included, is checked before it is written.
